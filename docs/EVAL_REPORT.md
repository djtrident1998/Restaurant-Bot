## Caveats

- Results vary run to run (the model's temperature can't be set). Across the runs made while building, v2's overall pass rate ranged 95.7%–100% and v1's 80–89%; the tables above are one run.
- The test set was used while tuning v2 (read the failures, changed the prompt), so v2's score is optimistic; a held-out set would be the next step.
- Two scorer false positives were fixed along the way (bold emphasis counted as a dish; decline wording), and the confirm-before-order code guard was tightened to require the read-back in an earlier turn. Both apply to v1 and v2.
- 46 cases is small: one case is ~2.2 points.

## Method

- Each case runs through the same `runAgent()` the production route uses, including the code-level input gate, tool validation and grounding check.
- Cart/total correctness is read from the server-side cart, not from the model's text.
- Hallucination = any reply with a ₹ amount not in the menu or tool results, or a bold dish name not on the menu.
- Temperature is not controllable on this model, so results can vary slightly between runs.
